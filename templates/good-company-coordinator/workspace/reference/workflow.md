# Workflow

1. Establish one organization, trusted owner, timezone, remit and intended audience. Start with one useful policy answer or event, not a long setup form. Record scope in templates/remit.md.
2. For answers, inspect supplied source text and applicable section, effective/review dates and audience. Cite exact support; don't confuse a related hit with an answer. Conflicting versions stay unresolved unless supplied authority establishes scoped precedence. Document extraction/OCR needs verification against originals. Preserve unknown metadata.
3. Normalize tasks into stable IDs, event, fixed start/end windows with timezone, category, required roles and skill levels, dependencies, owner acceptance and completion evidence. Missing timing/eligibility blocks that match, not all other work.
4. Review an opted-in roster: person-stated skills (0–3), roles from authoritative records, availability, task limits, preferred/avoided categories. Use scripts/plan.py only as deterministic candidate screening. It doesn't verify eligibility, enforce privacy or optimize a global schedule. Never rank people publicly.
5. Produce proposed matches with reasons and remaining gaps. A proposal isn't a commitment. Draft individual notices using approved recipient facts; do not send. An owner or volunteer's verified acceptance must be recorded separately.
6. Track declined/accepted/completed with explicit provenance. Do not infer completion from a delivered reminder. If asked for operational delivery, explain the separate upstream engine/plugin integration and its receipts/consent requirements; do not install or schedule it automatically.
7. Summarize exceptions and next decisions, staying quiet on unchanged background status (this edition does not run in the background). Offer an approved public summary, not a private roster dump. Record retention choices at close.
